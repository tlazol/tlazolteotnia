スキルは [GitHub の tlazol/skills](https://github.com/tlazol/skills) で公開している。
以下に `anti-poem` の全文を載せる。

```markdown
---
name: anti-poem
description: ユーザが文章を添削してほしい時に使用する。AIが生成した不要な文章を削減する場合に使う。
---
- 読み物としての演出より、設計資料としての情報伝達を優先して添削してください。
- 問いかけ、溜め、決め台詞、抽象的な意味づけを追加しないでください。
- 各文が、具体的な事実、設計判断、その根拠、条件、未確認事項のどれかを伝えているか点検してください。
- 「〜が判断に関わる」「〜が重要になる」のように、何をどう判断するかを示さない文は削除してください。
- 削っても情報が失われない文は、言い換えず削除してください。
- 緩急は説明の順序と段落分けで整え、演出のための文は足さないでください。
```

「簡潔に書いて」だけだと、情報のない文章が短くなって残ることがある。
そのため、「削っても情報が失われない文は、言い換えず削除してください」と指示している。

# 削りたい文章

ここで**ポエム**と呼んでいるのは、技術的な説明に足される、情報のない問いかけ、溜め、決め台詞、抽象的な意味づけのことだ。

例えば、次の文には設計の内容が書かれていない。

> ここで重要になるのが、キャッシュの設計だ。
> キャッシュをどう扱うかが、システム全体の設計判断に関わってくる。

キャッシュをどう設計したのかも、何を基準に判断したのかも書いていない。
これを「キャッシュ設計はシステム全体に影響する」と短くされても、やはり知りたいことは分からない。

設計判断と理由を書くなら、例えば次のようになる。

> 価格変更を即座に反映するため、商品価格はキャッシュしない。

ただし、元の文章にこの事実がなければ、添削で勝手に足さない。
判断の中身が分からないなら、書き手に確認する必要がある。

ちなみに GPT-6.1-Sol high に「なんでポエム書いちゃうの？」と聞いたら、

> 「読みやすく整える」を、前置きや問いかけ、締めの一言を足すこととして処理してしまうから。具体的な情報が増えていなくても、文章としてまとまって見えるので、説明が改善したと取り違える。今回の追記でも、最後の「今回の原稿では、演出に加えて重複した説明も削られた」は、直前の比較を言い直しているだけだった。

と、また死ぬほど読みにくいポエムをのたまってきたので anti-poem で添削したら、

> 僕自身が「節をまとめる一文を置きたい」という癖を優先してしまった。ここは削ってよかった。

とのことだった。

# 添削の例

削る対象を説明するために作った例を載せる。

添削前。

> なぜ、処理をキューに入れるのか。
> その答えは、外部 API の応答時間にある。
> 外部 API の応答には数秒かかるため、メール送信をキューに入れ、画面には受付完了を先に返す。
> これは単なる非同期化ではない。ユーザー体験を見つめ直す設計判断だ。

添削後。

> 外部 API の応答には数秒かかるため、メール送信をキューに入れ、画面には受付完了を先に返す。

処理の内容も、その理由も残っている。
前後の演出を削るだけで、説明としては足りるのだ。

# この記事自体の添削結果

この記事の原稿も `anti-poem` で添削した。

「$anti-poem というスキルを作ったよという記事を書いて。最近の記事を2,3件見て、口調を合わせてね」

というプロンプトで生成された記事から、添削された箇所を抜粋する。

## 重複した説明をまとめる

添削前。

> 「簡潔に書いて」だけだと、情報のない文章が短くなって残ることがある。
> だから、何を残して何を削るのかまで書いた。
>
> 特に入れたかったのは「削っても情報が失われない文は、言い換えず削除してください」だ。
> 不要な一文を別のかっこいい一文に直されても困るので、削除まで指示している。

添削後。

> 「簡潔に書いて」だけだと、情報のない文章が短くなって残ることがある。
> そのため、「削っても情報が失われない文は、言い換えず削除してください」と指示している。

指示を入れた理由と指示そのものを残し、同じ意図を繰り返す説明をまとめている。

## 例の後の補足を削る

キューの添削例の直後には、次の二文があった。

> 処理の内容も、その理由も残っている。
> 前後の演出を削るだけで、説明としては足りるのだ。

添削後は、この二文を削除した。
直前の比較から分かる内容なので、別の表現への言い換えもしていない。

一方、元の文章にない事実を足さないことや、「失敗する可能性がある」のような不確実性を残す説明は、添削後にも残っている。
今回の原稿では、演出に加えて重複した説明も削られた。

# おわりに

AI のポエムを許してはいけない。

ただでさえ認知負荷でつらいのに、The AI みたいな文章を読まされるともう無理になる。

これは心の平穏を保つためのスキルなのだ。
